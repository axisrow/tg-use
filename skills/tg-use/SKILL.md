# tg-use: малый обход бота и сценарий

CLI ставится один раз: `pip3 install tg-use` и `python3 -m playwright install chromium`.
Браузерная механика — в скилле `browser-use` (`browser-use skill install`); этот
скилл — только профильный нюанс и процедура. В CLI нет модели: решения принимаешь
ты, `tg-use` — только руки (login/open/state/click/save/test).

## Подготовка

1. `tg-use login` — headed-браузер с профилем `~/.tg-use-agent-profile`
   (= пароль от аккаунта; не коммитить, не чистить). Адрес живого браузера он
   пишет в `~/.tg-use-cdp`; окно не закрывать до конца работы. Повторный запуск
   QR не требует. Хочешь работать с этим браузером сам через browser-use —
   подключайся по `BU_CDP_URL=$(cat ~/.tg-use-cdp)`, это тот же Chromium.
2. `tg-use open @bot` — CLI сам находит чат по username через поиск
   webk и открывает его, проверяя peer-id (guard от чужого чата); ничего не
   отправляет. Руками в браузере ничего не открываем. Сразу после `login`
   поиск webk бывает глух — CLI сам будит поле настоящей клавишей (#27);
   поиск не ответил — это неисправность: сообщи владельцу, не жди и не повторяй.
3. `tg-use state` — убедись, что чат отвечает. Если бот ещё не
   стартовал (пусто), `/start` уходит одностадийным сценарием — `test` с шагом
   `{"do": {"send": "/start"}}`.

## Малый обход (глубина ≤2, до ~5 состояний)

Цикл, каждый шаг — вызов CLI; темп задаёшь ты: пауза 2–3 c между вызовами.
Ошибка «страница webk не смонтирована» — повтори `open @bot`.

1. `tg-use state` → JSON `{id, text, buttons, reply_buttons}` (reply_buttons —
   нижняя reply-клавиатура бота; click жмёт и её кнопки).
2. `tg-use save --bot @bot` — первое состояние (корень); дальше
   `save --from <id> --button "<label>"`.
3. Выбери кнопку сам; лучше
   не «API Token» (токен будет замазан скрабом). `tg-use click "<label>"` —
   вернёт новое состояние; ошибка = битое ребро, пометь и не повторяй.
4. Новое состояние → `save --from <id_родителя> --button "<label>"`.
5. Вложенные уровни: из нового состояния один шаг вглубь (итого ≤2 от корня),
   не более ~5 состояний. Достаточно для карты меню.

Артефакты: `artifacts/flow.json` + `artifacts/flow.md` (Mermaid) — CLI
перезаписывает их после каждого save, прерванный обход оставляет валидный след.

## Сценарий

Сохрани `artifacts/<bot>.scenario.json`:
`[{"do": {"send": "/mybots"} | {"click": "<label>"}, "expect": {"contains"|"regex": "..."}}]`
и прогони: `tg-use test artifacts/<bot>.scenario.json` → `artifacts/report.json`
(pass/fail по шагам + латентность), падение = exit 1. `send` шлёт любой текст
в диалог бота, не только `/`-команды — свободный ввод опросников проходит им.

## Правила безопасности (не упрощать)

- Только диалоги с ботами; ни одного сообщения живым людям.
- PNG не снимаем; текст артефактов и так проходит скраб токенов.
- Деструктивное не выбирай: любое решение — твоё, в моменте; CLI ничего не запрещает.
